## 2. ThaiWater API — รายละเอียด (แหล่งหลัก)

### 2.1 Endpoint และการเรียก

```text
GET https://api-v3.thaiwater.net/api/v1/thaiwater30/public/waterlevel?province_code=95
Headers: accept: application/json
         user-agent: yala-flood-app/0.1.0
```

- ไม่ต้อง API key
- โค้ดอ้าง: `mobile/app/lib/config/app_config.dart` → `waterLevelUrl`
- ตัวช่วย: `mobile/app/lib/services/thai_water_service.dart` (timeout 12 วินาที, retry 2 ครั้ง, backoff 900 ms)

### 2.3 พฤติกรรมจริงที่วัดได้

| ประเด็น | ผลการวัด | ผลกระทบ |
|---|---|---|
| สถานะการตอบ | `HTTP/2 200` ทุกครั้งที่ probe | ใช้งานได้ |
| จำนวน record | 14 (ผ่าน `province_code=95`) | ตรงเป้า |
| **ความถี่จริง** | `waterlevel_datetime` กระจุกที่ `20:00`, `21:00`, `21:30` → **~30 นาที** (บางสถานีรายชม.) | ต้องปรับคาดการณ์: poll 10 นาทีแต่ข้อมูลอาจเปลี่ยนทุก 30 นาที |
| HTTP cache headers | **ไม่มี** `Cache-Control`/`ETag`/`Last-Modified` | แคชได้เฉพาะฝั่ง client ตามเวลา |
| rate-limit headers | ไม่มีข้อมูล | ใส่ polite interval + retry ไว้ |
| `station_code=` query | **ถูกมองข้าม** (คืน 14 สถานีเสมอ) | กรองสถานีทำ client-side |
| `/rainfall` บน service เดียวกัน | `404 Unknown service id` | ฝนต้องไป TMD แยก |
| `situation_level` เป็น null | 5/14 สถานี | ต้องมี fallback เทียบตลิ่ง |
| `left_bank = 0` | 2/14 สถานี (ฝายละแอ, เขื่อนบางลาง) | คำนวณ W จากตลิ่งไม่ได้ |
| `storage_percent` เป็นลบ | 1 สถานี (FOP045 `-0.31`) | ตั้งค่า anomaly flag |

### 2.4 SLA และสิทธิ์การใช้งาน

| หัวข้อ | สถานะ |
|---|---|
| SLA เป็นทางการ | **ไม่พบ** — เอกสารเปิดไม่ได้ระบุ uptime เป็นทางการ; ใช้เป้าใน PRD (≥95% สำเร็จ, timeout ≤5 s) |
| timeout ที่ใช้จริง | 12 วินาที + retry 2 ครั้ง (900 ms backoff) — รันให้นิ่งกว่าเป้า |
| สิทธิ์การใช้งาน | เปิดสาธารณะ ไม่ต้อง key; เป็นข้อมูลของ กรมทรัพยากรน้ำ/สสน. — **ต้องใส่ที่มา**; เงื่อนไขการ re-host ยัง **ต้องยืนยัน** ก่อน Phase 2 (ต่อให้เป็น open data ก็ควรอ้างแหล่ง) |
| ข้อควรระวัง | ไม่ re-host ชุดข้อมูลใหญ่ซ้ำ; ใช้ snapshot + manifest และ purge ตาม retention |

| D6 | ไม่มีข้อมูลย้อนหลัง 30 วัน | หา `H_normal` ไม่ได้ | bootstrap rule + flag ความมั่นใจ |
| D7 | sensor ผิด (outlier) | คะแนนหลอน | validator + outlier detection |
| D8 | สิทธิ์ re-host ไม่ชัดเจน | ความเสี่ยงทางกฎหมาย | ใส่ที่มา + ยืนยัน ToS ก่อน Phase 2 |

## 7. แผน Fallback / Fail-Closed

> **Fail-closed** = เมื่อข้อมูลไม่น่าเชื่อถือ ให้ **ไม่** คำนวณคะแนน/ไม่ส่งแจ้งเตือนใหม่
> ยึดข้อมูลล่าสุดที่ผ่าน validation + แสดงป้ายชัดเจน

| สถานการณ์ | พฤติกรรม |
|---|---|
| ThaiWater timeout / non-200 | retry 2 ครั้ง → แคชล่าสุด + ป้าย "ข้อมูลล้าสมัย" |
| แคชเกิน 30 นาที (น้ำ) | `stale=true` → ไม่คำนวณ score ใหม่, แสดงข้อมูลเดิม |
| ข้อมูลฝนเกิน 60 นาที | R=0 และระบุ "ยังไม่มีข้อมูลฝน" |
| ข้อมูลไม่ครบ 14 สถานี | รับเฉพาะรายการที่ validate ผ่าน + `partial=true` |
| `situation_level` เป็น null | เทียบระดับน้ำกับตลิ่ง; ตลิ่ง 0/ขาด → W=0, `water_signal=false` |
| `storage_percent` ผิดปกติ (เช่น ลบ) | ไม่ใช้ + ตั้ง anomaly flag |
| manifest hash ไม่ตรง | แอพปฏิเสธ snapshot (ใช้แคชเดิม) |
| snapshot อ่านไม่ได้ | โหมดออฟไลน์ ใช้แคชในเครื่อง + เบอร์โทร |
| Push ล้มเหลว | fallback ช่องทาง: Dashboard เว็บ, SMS/Line OA (ภายหลัง) |
